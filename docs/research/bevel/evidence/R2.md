## Item 1: Cardio and Muscular calibration gate (RESOLVED)

### Cardio writer 0x1015efbc4

- 0x1015f0184..0x1015f019c: `d10 = min(1.0, N / 28.0)`.
  - N is the Int stack argument `[x29+0x10]`.
  - N is the running count of `load > 5.0` flags over the last 42 days.
  - Push helper 0x100009ea4: `flag = 5.0 < load`; removeFirst once the count before append is greater than 0x29.
- 0x1015f01b8: `d15 = 0x3fd6666666666666` (0.35).
- 0x1015f0398: `bl 0x10000ad88` (recency), then `fcmp d0,d10; fcsel d0,d0,d10,mi`. This is min(recency, density).
- `fcmp d0,d15; b.pl` continues to the ratio logic. Otherwise the status is calibrating (w25 = 0).
- The same gate appears again at 0x1015f050c for the post-workout status.

### Recency 0x10000ad88

- n = count of the 28-day load window. n < 2 gives 0.
- For i in 0..n-2, with ago = (n-2)-i: add `1 + ago*(-0.0625)` (x11 = 0xBFB0000000000000) when `load[i] > 5.0 && ago < 16` (`ccmp x13,#0x10 … lt`).
- Result: min(1, 0.25*acc).

### Cardio UI builder 0x10000ae0c

- 0x10000b3f4: ctlMaturity `d15 = min(1, CTL/30)`, or d11 (0) when there is no entry. Display only.
- 0x10000b414: `d14 = min(1, N/28)`.
- 0x10000b42c: `d10 = min(recency, d14)`.
- 0x10000b4b8: `fcmp d10, 0.35; b.pl` continues; below 0.35 the status is calibrating.

### Muscular 0x10008bd08 (0x10008c124..0x10008c298)

- ctlMaturity `d2 = min(1, CTL/1500)` (0x4097700000000000). It is not used in the gate.
- `d8 = min(1, N/28)`.
- Recency loop threshold is s15 (250).
- `d3 = min(recency d10, d8)`.
- `fcmp d3,0.35; b.mi` gives calibrating, and `fcmp s13 (prevCTL),#0; b.ls` gives calibrating.

```ts
const trainingDensity = Math.min(1, activeDaysInLast42 / 28);  // active: load > 5 (cardio) / > 250 (muscular)
const confidence = Math.min(trainingDensity, recency(last28));   // recency excludes today
if (confidence < 0.35) status = calibrating;                      // muscular also: prevCTL <= 0 -> calibrating
// ctlMaturity = min(1, CTL/30) cardio, min(1, CTL/1500) muscular: UI field only
```

Correction: B G07 reads `ctlMaturity = min(historyDays/28, 1)` in the gate. That value is actually trainingDensity, and ctlMaturity is never part of the gate.

## Item 7: Trend baselines and windows (RESOLVED; corrects other-calculators.md)

### Registrar 0x101dacaa0

Arguments: metric x0, reference date x2 → [0x140], and x3 = a dict from metric to (series, kind).

### Status band ±1 SD

Call at 0x101dadbf0 → 0x101f7a2f8, default path 0x101dadbd0.
- `currentValue` = last point of `selectedData`. 0x101f69628 returns TrendDetailPayload.selectedData (0x10524ad6c: dynamicRange | benchmarkRange | standard). 0x10194a1ec maps the points and 0x10005d72c takes the last one.
- `baselineAverage`, `baselineStdDev` = 0x10183d970 applied to 0x101dc3358(0x10194b6d8(selectedData, kind)). That is a Welford Float32 pass over all non-nil values: `mean += (x-mean)/n; M2 += (x-oldMean)*(x-mean)`, then `sd = sqrt(M2/n)` (POPULATION). n = 0 gives nil.
- So the baseline is the mean and SD of the points in the trend window the user is viewing (LookbackPeriod 7d/14d/30d/3m/6m/1y/YTD with its AggregationType). The current point is included. It is NOT the 60-day per-day baseline.

### Trend direction ±5%

Call 0x1002d2158(metric, refDate, series = dict[metric], kind, judgement).

Judgement mode by metric (metric enum indices from the record table at 0x105bc2c84):

| Mask | Metrics | Mode |
|---|---|---|
| A 0x807342edf33f and C 0x6bc004002a | restingHeartRate, respiratoryRate, daytimeHeartRate, timeToFallAsleep, stressScore, inactiveStress, sleepStress, temperature, bodyTemperature | 1 decreaseGood |
| A, metric 15/16 | wakeTime, sleepTime | 3 increaseAndDecreaseBad |
| A, everything else | recoveryScore, heartRateVariability, heartRateDip, sleepBank, sleepScore, timeAsleepMinutes, timeRemSleepMinutes, timeDeepSleepMinutes, exerciseMinutes, activeCaloriesBurned, totalCaloriesBurned, strainScore, steps, spO2, nutritionScore | 0 increaseGood |
| B 0x7000000000000 | glucoseAverage, glucoseVariability, morningFastingGlucose | 5 benchmark |
| netEnergy (0x29) | netEnergy | own path 0x1002d2694 |
| none | every other metric | no direction analysis (0x1002d2678) |

Series preparation:
- 0x1002d4838: `start` = timestamp of the series' last element, or ref − 365 d when the series is empty.
- 0x1002d47a8: when start < ref, it builds the calendar days start…ref (0x1030dd1b8 → 0x1030e9e04, noon-stepped and inclusive) and reverses them into ascending order (0x101848764).
- The result is appended AFTER the series as nil-valued points (`Array.append(contentsOf:)` 0x1017e4d5c → 0x1017e88b4).
- The padding starts at the last element and runs forward to the reference day. So the input series is ascending (oldest first) and missing recent days become trailing nils.
- 0x1002d5694 then applies the per-kind bucketing (0x1002d2a90 / 0x1002d2cf0 / 0x1002d2f50 / 0x1002d31e4).
- Points are kept when their date is before `startOfDay(ref) + 1 day` (loop in 0x1002d2158).

Direction 0x1002d62f8, per N in [3, 7, 14, 30, 90]:
- `p = (last − first)/|first|` over the last N+1 daily points.
- p >= 0.05 is increase; p <= −0.05 is decrease.
- Either end nil gives nil.
- The comparison point is the value N days earlier. There is no separate baseline.
